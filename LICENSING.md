# Licensing

*Status: proposed. The actual license files have not been added yet.*

## What is covered

| Part of the repository | Proposed license |
|---|---|
| Code and scripts (`tools/`) | A permissive open-source software license such as MIT or Apache 2.0 |
| Documentation, method guide and templates (`docs/`, `templates/`, `schema/`, `README`, `DESIGN`, `PROTOCOLS`) | Creative Commons Attribution-ShareAlike 4.0 (CC BY-SA 4.0), or a more permissive Creative Commons license if preferred |
| Demo in a fictional language (`examples/`) | Same as documentation |

## What is never covered

**Community language content is not covered by any license in this repository, and these licenses do not apply to it.**

Anything a community adds to its own copy of the toolkit, including words, sentences, stories, recordings, images and grammar knowledge, remains the property of that community, under whatever terms the community decides. Copying the template does not transfer, grant or imply any rights over that content to the project, its maintainer or anyone else.

## Reasoning

- A permissive code license lets communities, schools and other developers use and adapt the tools freely, with little legal friction.
- ShareAlike on the documentation encourages improvements to the method to flow back to everyone, while still allowing communities to use and adapt it.
- Keeping content entirely outside these licenses matches PROTOCOLS.md.

## Before this is final

- Choose the exact code license. MIT is simplest. Apache 2.0 adds an explicit patent grant. GitHub's "Add a license" picker can add the standard text when you choose.
- Decide whether ShareAlike is the right choice for the documentation. It requires derivatives to use the same license, which some adopters prefer to avoid.
- Consider whether an Indigenous-specific notice, such as a Traditional Knowledge or Local Contexts label, belongs on parts of the project. This is a question for pilot communities and any advisory group, not a decision to make alone.
- Have a person with legal knowledge confirm the wording before the project is promoted widely. This file is a plain-language plan, not legal advice.
